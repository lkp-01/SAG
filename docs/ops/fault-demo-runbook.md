# 故障演示 Runbook（秒级发现 + 持久化留痕）

目标：在现场可稳定演示“故障注入 -> 秒级发现 -> 审计追溯”的完整闭环。

---

## 1. 演示目标

1. **识别**：某 API 延迟明显超基线或请求超时。
2. **告警**：`/ops/workflow` 与 `/ops/observability` 在秒级出现异常信号。
3. **留痕**：`/ops/audit` 可按时间/服务/结果追溯故障记录。

---

## 2. 演示前检查（3 分钟）

1. 打开 `http://<服务器IP>:3001/ops/self-check`，确保核心服务 `ok`。
2. 打开：
   - `http://<服务器IP>:3001/ops/workflow`
   - `http://<服务器IP>:3001/ops/observability`
   - `http://<服务器IP>:3001/ops/audit`
3. 记录当前基线（正常时）：
   - 关键 API P95
   - 错误率
   - 最近 5 分钟请求量

---

## 3. 故障注入剧本

## 剧本 A：人为注入慢请求（推荐）

适用：演示“时延超过基线”。

操作建议（任选其一）：
- 在测试环境目标 API 增加固定延迟（如 800ms / 1500ms）。
- 或在链路节点临时加网络延迟（`tc netem delay`）。

预期现象：
- `/ops/workflow` 中对应节点 P95 / P99 快速抬升。
- `/ops/observability` 的 Grafana / Prometheus 曲线出现突变。
- `/ops/audit` 中该服务请求 `latency_ms` 明显增大。

## 剧本 B：人为注入超时/不可用

适用：演示“秒级发现故障应用”。

操作建议（任选其一）：
- 临时下线某后端服务实例（仅测试环境）。
- 注入短时网络中断，触发上游超时。

预期现象：
- `/ops/workflow` 出现 `ERR` 或错误率升高。
- 自检页健康状态出现异常。
- 审计记录中出现失败结果（如 5xx / timeout）。

---

## 4. 演示执行节奏（建议 5 分钟）

1. 先展示“正常状态”指标。
2. 执行剧本 A 或 B（30~60 秒内）。
3. 现场刷新 `/ops/workflow` 展示异常出现。
4. 打开 `/ops/audit` 按时间窗口查询并展示留痕字段。
5. 解除故障并展示恢复过程（可加一句“发现与恢复耗时”）。

---

## 5. 审计追溯推荐筛选条件

- `service`: `control-plane-admin` / `sag-auth` / `sag-policy` / `zentinel`
- `result`: `200` / `5xx` / `timeout`
- `time range`: 故障注入前后 5 分钟
- 补充维度：`user_id`、`app_id`、`path`、`trace_id`

关键展示字段：
- `timestamp`
- `service`
- `path`
- `latency_ms`
- `result`
- `decision`
- `trace_id`

---

## 6. 持久化记录建议（演示后沉淀）

每次演示结束，沉淀一条“故障演示记录”：

| 字段 | 示例 |
|---|---|
| 演示时间 | 2026-04-14 14:30 |
| 故障类型 | latency spike / timeout |
| 影响服务 | sag-auth |
| 首次发现耗时 | 8s |
| 恢复耗时 | 45s |
| 审计追溯链接 | `/ops/audit?...` |
| 结论 | 秒级发现，分钟级恢复 |

建议将该表统一归档到团队运维周报或演示记录库。
