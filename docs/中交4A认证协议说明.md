# 中交4A认证协议说明

> 本文档仅描述中交4A平台本身的认证协议，供其他系统对接参考。

---

## 一、前置准备

对接4A前需要在4A平台注册应用，获取以下凭证：

| 参数 | 说明 |
|------|------|
| `client_id` (corpid) | 应用唯一标识 |
| `client_secret` (corpsecret) | 应用密钥 |

同时从4A平台获取以下接口地址（共5个）：

| 地址 | 用途 |
|------|------|
| `firstUri` | 4A登录页地址（浏览器跳转） |
| `secondUri` | 用授权码换取 access_token 的地址 |
| `thirdUri` | 用 access_token 换取用户信息的地址 |
| `tokenUrl` | 直接用 corpid/corpsecret 换 access_token 的地址 |
| `userInfoUrl` | 用 access_token + code 换取用户ID的地址 |

---

## 二、4A提供两种认证模式

### 模式一：OAuth2授权码模式（交建通扫码）

标准 OAuth2 Authorization Code 流程，适合浏览器端。

```
用户浏览器         你的系统后端              4A平台
    │                  │                     │
    │ ①跳转4A登录页     │                     │
    │────────────────────────────────────────>│
    │                  │                     │
    │ ②用户扫码/登录    │                     │
    │    4A回调带code   │                     │
    │<────────────────────────────────────────│
    │                  │                     │
    │ ③传code给后端     │                     │
    │────────────────>│                     │
    │                  │ ④code换token         │
    │                  │   POST secondUri     │
    │                  │────────────────────>│
    │                  │ ⑤返回access_token   │
    │                  │<────────────────────│
    │                  │                     │
    │                  │ ⑥token换用户信息     │
    │                  │   GET thirdUri       │
    │                  │────────────────────>│
    │                  │ ⑦返回employeeNumber │
    │                  │<────────────────────│
```

#### 步骤①：跳转4A登录页

浏览器跳转到 `firstUri`，4A展示登录/扫码页面。

#### 步骤②：用户完成认证，4A回调

用户在4A完成认证后，4A将浏览器重定向回你的回调地址，URL上带 `code` 参数：

```
https://你的回调地址?code=授权码
```

#### 步骤③：前端将code传给后端

#### 步骤④⑤：用code换取access_token

```
POST {secondUri}
Content-Type: application/x-www-form-urlencoded

client_id=你的client_id
&client_secret=你的client_secret
&code=上一步拿到的授权码
&grant_type=authorization_code
```

**成功响应：**

```json
{
    "access_token": "xxx",
    "refresh_token": "xxx",
    "uid": "xxx",
    "token_type": "xxx",
    "expires_in": "xxx"
}
```

**失败响应：**

```json
{
    "errcode": "错误码",
    "msg": "错误信息"
}
```

#### 步骤⑥⑦：用access_token换取用户信息

```
GET {thirdUri}?access_token=上一步的token&client_id=你的client_id
```

**成功响应：**

```json
{
    "employeeNumber": "用户工号",
    ...其他字段
}
```

**失败响应：**

```json
{
    "errcode": "错误码",
    "msg": "错误信息"
}
```

**关键字段：`employeeNumber`** —— 这是4A返回的用户唯一标识（工号），用这个值在你的系统中匹配用户。

---

### 模式二：4A内置模式（类似企业微信API）

不需要浏览器跳转，后端直接调用4A接口。适合非浏览器场景（如移动端APP、内部服务间调用）。

```
你的系统后端              4A平台
    │                     │
    │ ①获取access_token   │
    │   GET tokenUrl      │
    │────────────────────>│
    │ ②返回access_token   │
    │<────────────────────│
    │                     │
    │ ③用token+code换用户  │
    │   GET userInfoUrl   │
    │────────────────────>│
    │ ④返回UserId         │
    │<────────────────────│
```

#### 步骤①②：获取access_token

```
GET {tokenUrl}?corpid=你的client_id&corpsecret=你的client_secret
```

**成功响应：**

```json
{
    "errcode": 0,
    "access_token": "xxx",
    "expires_in": 7200
}
```

**说明：**
- `expires_in` 默认7200秒（2小时）
- **建议缓存**此token，避免频繁请求。缓存时提前5分钟失效（即有效期取 `expires_in - 300`）

#### 步骤③④：用access_token + code获取用户ID

这里的 `code` 来源取决于具体场景（可能是4A推送的、或者前端传过来的）。

```
GET {userInfoUrl}?access_token=上一步的token&code=授权码
```

**成功响应：**

```json
{
    "errcode": 0,
    "UserId": "用户ID"
}
```

## 三、两种模式对比

| 对比项 | OAuth2模式 | 4A内置模式 |
|--------|-----------|-----------|
| 适用场景 | 浏览器端、扫码 | 后端直接调用 |
| 凭证参数名 | client_id / client_secret | corpid / corpsecret |
| 获取token方式 | POST + form表单，需传code | GET，不需code |
| 获取用户方式 | GET，传access_token + client_id | GET，传access_token + code |
| 用户标识字段 | `employeeNumber` | `UserId` |
| token是否可缓存 | 否（一次性） | 是（有效期2小时） |

---

## 四、对接要点总结

1. **拿到5个URL + 2个凭证**，从4A平台管理员处获取
2. **选择认证模式**：浏览器场景用OAuth2模式，非浏览器场景用4A内置模式
3. **4A的错误格式统一为** `{"errcode": "xxx", "msg": "xxx"}`，调用后先检查此字段
4. **4A返回的用户标识**：OAuth2模式是 `employeeNumber`，内置模式是 `UserId`，本质都是用户工号
5. **4A内置模式的token要缓存**，有效期2小时，建议提前5分钟刷新
