# Kimi 一键指令：生成「竞标/立项汇报」PPT

> **用法**：将下方 **「从下一行开始」至文件末尾标记** 的整段复制到 Kimi（或其它支持长上下文的 AI），一次发送即可。  
> 发送前可将 `{客户名称}`、`{汇报日期}`、`{汇报人/部门}` 替换为实际值。

---

**【开始复制】**

你是一名资深 **企业软件售前顾问** 与 **PPT 信息设计师**。请基于以下 **产品事实与边界**（来自 SAG Cloud 项目文档），生成一套 **中文竞标/立项汇报风格** 的 PPT 材料。

### 一、产品基本信息（必须遵守，勿编造客户案例）

- **产品名**：SAG Cloud 安全接入网关（Secure Access Gateway，SAG）。
- **形态**：企业内外网隔离场景下的 **零信任安全接入网关**；当前为 **可运行原型 + Docker Compose 交付基线**，含 **双机（边缘/内网）部署模板**。
- **阶段表述**：Phase-1：**单机构图 + 双机模板 + 运维控制台与观测基线**；适合 PoC、技术验证与产品化迭代，**非完整商用产品线**（未完结模块应标注“规划/预留”）。

### 二、标准数据面路径（架构图必须按此顺序）

请用 **一张主架构图** 表达，箭头方向从左到右或从上到下：

`Client → Zentinel（北向 HTTPS）→ http-tunnel-bridge → stealth-tunnel-agent（策略/IAM 前检）→ sag-connector → APISIX（内网 L7）→ 业务上游`

补充说明（可放在备注或小字）：

- `sag-connector` **必须**配置 `SAG_APISIX_BASE_URL`；**APISIX 为内网 L7 标准路径**。
- 隧道路由由 **control-plane-admin** 维护；**`connector_endpoint` 必须与运行中的 `SAG_CONNECTOR_ID` 对齐**，否则会出现隧道不健康等问题。

### 三、控制面与身份策略（各一页或合并一页）

- **控制面**：`control-plane-admin`（路由与内网上游、可选 APISIX 下发）、`sag-auth`、`sag-policy`。
- **身份**：本地账号 + JWT；支持 **4A OAuth2 授权码模式**（配置齐全启用 `/api/v1/auth/sso/*`）；甲方的统一身份未开放时可用仓库内 **Fake 4A** 做端到端浏览器演示。
- **策略**：`sag-policy` 为 PDP；隧道层转发前可调用策略；门户可演示 **访客/未认证拦截**。

### 四、运维与可观测（强调“可验收”）

- **栈**：Prometheus、Grafana、OTel Collector；各组件暴露 metrics（含 Zentinel `:9090/metrics`）。
- **管理端**：`frontend-admin-next`（默认 `:3001`）— 工作流、指标、硬件视图、应用/API 树；兼容控制面板 `/control`。
- **健康语义**：不仅看进程 **up**，还需 **业务探针**：
  - **T1**：`http://<host>:9000/api/test`（bridge 路径）
  - **N1**：`http://<host>:3001/api-zentinel/api/test`（经管理端代理的北向探测）
  - 若 **N1=5xx 且 T1=200**，优先排查 **Zentinel TLS / SNI / 证书链**（文档结论）。

### 五、部署与端口（列表一页，表格呈现）

主路径：`docker compose build && docker compose up -d`；**Zentinel 为默认服务**。

至少列出端口：**8090**（控制面）、**8080**（认证）、**8081**（策略）、**9000**（bridge）、**10080**（Zentinel）、**9080/9180**（APISIX）、**9091**（Prometheus 映射）、**3000**（Grafana）、**3001**（管理端 Next）、**5174**（门户）。  
（说明：具体映射以现场 `docker-compose` 为准。）

### 六、可靠性与安全（“已验证类”表述要克制）

- **Fail-closed**：错误 SNI、错误隧道 endpoint、Agent 停止等场景下，数据面 **按预期失败**；恢复正确参数与服务后可恢复。
- **TLS**：`SAG_GRPC_TLS_SERVER_NAME` 须与证书一致；北向访问主机名须在证书 **SAN** 内；客户端需信任 **CA**（如 Node `NODE_EXTRA_CA_CERTS`）。
- **双机**：强调 **路由 connector_endpoint 与 connector ID 对齐**、TLS/DNS 一致。

### 七、差异化与路线图

- **差异化**：分层清晰可安全评审；**端到端 PoC 路径完整**；身份与策略可组合；观测与探针可验收。
- **路线图（诚实）**：Mesh 等为 **预留**；终端安全、审计风控等见仓库规划占位，**不可写成已交付**。

### 八、输出要求（你必须交付的内容）

1. 先给出 **PPT 目录（每页标题一行）**，建议 **20～24 页**。
2. 再 **逐页输出**：
   - 标题  
   - 3～6 条要点（`•` 开头）  
   - **本页一句话结论**  
   - **配图建议**（架构图/表格/流程图/截图占位）  
   - **演讲者备注**（1～3 句口语）  
3. **视觉风格**：深蓝/科技蓝主色，白或浅灰底；少字、多结构图；避免营销夸张词。
4. **禁止**：虚构客户名称、合同金额、未给出的性能数字；未实现能力不得写“已商用”。

### 九、占位符（请替换）

- 客户：`{客户名称}`
- 日期：`{汇报日期}`
- 汇报人：`{汇报人/部门}`

**【结束复制】**
