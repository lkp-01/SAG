# PPT 逐页规格（细化版）

本文档与 [`kimi-ppt-prompt.md`](./kimi-ppt-prompt.md) 配合使用：  
- **给 Kimi**：可将本文件核心约束 **追加** 到 `kimi-ppt-prompt.md` 之后，限制页序与每页必含元素。  
- **给人**：打印或对照修改，保证汇报口径与仓库一致。

---

## 1. 建议总页数与节奏

| 参数 | 建议值 |
|------|--------|
| 总页数 | 20～24（含封面与封底） |
| 每页要点 | 3～6 条，每条不超过两行 |
| 架构/流程图 | 至少 2 页（总体架构 + 数据面序列） |

---

## 2. 建议页序与每页必须包含的内容

以下为 **推荐标题**；生成时可微调，但 **不要删除** 标 ★ 的实质内容。

| # | 建议标题 | 必含元素 |
|---|----------|----------|
| 1 | 封面：SAG Cloud 安全接入网关 | 产品名、副标题（零信任/内外网安全接入）、客户占位、日期 ★ |
| 2 | 汇报议程 | 4～6 个章节锚点（背景→方案→架构→安全→部署→路线） |
| 3 | 背景与痛点 | 内外网隔离、API 暴露风险、身份与策略需求（表格） |
| 4 | 建设目标与范围 | 目标列表 + **当前阶段 Phase-1 边界**（原型/PoC，诚实）★ |
| 5 | 方案总览（一页） | **一句话价值** + 五大分层关键词（边界/隧道/策略/内网L7/控制面）★ |
| 6 | 标准数据面路径 ★ | 完整链路：**Zentinel→bridge→agent→connector→APISIX→上游** |
| 7 | 控制面组成 | 三组件：control-plane-admin、sag-auth、sag-policy；各 1 行职责 |
| 8 | 身份与 SSO | 本地 JWT；4A OAuth2；Fake 4A 演示定位（无甲方接口时）★ |
| 9 | 策略与零信任 | PDP、sag-policy；隧道前检；门户预检/访客演示（不夸大） |
| 10 | 内网 L7：APISIX | **连接器必配 APISIX**、标准路径表述 ★ |
| 11 | 可靠性与 Fail-closed | 错误 SNI/endpoint/Agent 停机 → 失败可预期；恢复路径 |
| 12 | TLS / SNI / 证书治理 | SAN 与访问域名一致；CA 注入；**新环境 openssl 预检**（见部署文档）★ |
| 13 | 运维可观测 | Prometheus/Grafana；metrics 覆盖链；工作流与 N1 补充语义 |
| 14 | 管理端与用户端 | `:3001` Next 控制台；`:5174` 门户；`/control` 兼容 |
| 15 | 部署方式 | Docker Compose 主路径；Zentinel 默认启用；冷启动编译耗时说明（不混淆为配置滞后）★ |
| 16 | 端口与组件一览 | 表格：8090/8080/8081/9000/10080/9080/9180/9091/3000/3001/5174 |
| 17 | 验收与探针 ★ | **T1** `:9000/api/test`；**N1** `:3001/api-zentinel/api/test`；冒烟脚本 |
| 18 | 双机部署要点 | edge/intra 模板；connector_endpoint 与 connector ID；TLS/DNS |
| 19 | 差异化优势 | 分层可评审、PoC 闭环、可演进（预留 Mesh 等如实写） |
| 20 | 风险与后续路线 | 未交付模块不写“已商用”；建议预编译镜像、正式 4A 联调 |

> 若需压缩到 18 页：合并 8+9、13+14、17+18。

## 3. 视觉与版式约束（给设计或 Kimi）

- **主色**：深蓝 `#0B2A5B` 或接近色；**辅色**：青/浅蓝高亮箭头。  
- **字体**：中文黑体/微软雅黑；英文 Arial/Helvetica；避免一页超过 40 字（标题除外）。  
- **架构图**：左“外网/用户”，右“内网/应用”；隧道用 **虚线管道** 表示。  
- **图标**：锁（TLS）、盾牌（策略）、云（接入）、服务器（内网）。  
- **禁止**：卡通插画、过多渐变、满屏小字。

---

## 4. 术语表（PPT 中首次出现可加脚注）

| 术语 | 简短解释 |
|------|----------|
| Zentinel | 北向 HTTPS 接入代理（边界层） |
| stealth-tunnel-agent | 隧道 Agent，gRPC，同步路由，策略前检 |
| sag-connector | 内网连接器，将隧道流量转 HTTP 至 APISIX |
| APISIX | 内网 L7 网关（数据面 9080） |
| PDP | 策略决策点，本项目中主要为 sag-policy |
| T1 / N1 | 数据面验收探针：bridge 路径 / 北向经管理端代理路径 |

---

## 5. 口径红线（汇报时必须统一）

1. **未开源/未承诺的能力** 不写“已上线生产”。  
2. **性能数据** 无实测则不写 QPS/TPS 数字。  
3. **甲方 4A** 写“支持协议对接 + Fake 演示”，正式环境以联调为准。  
4. **Zentinel 启动**：可写“冷启动可能编译较久”，**不写**“因此配置会过期或滞后”（与事实不符）。

## 6. 可选附录页（按需加在 Q&A 前）

- **A1**：`smoke-dataplane` 脚本结果示意（PASS/FAIL 表格，无真实数据则写“示例”）。  
- **A2**：双机故障注入结论摘要（错误 SNI/endpoint/停 Agent → 预期失败）。  
- **A3**：与纯 VPN / 仅 WAF 的对比表（各 3 行）。
